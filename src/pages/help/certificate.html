Certificate error when connecting a PC

Connecting a PC fails with something answered … but it is not the server this code was made for, or with an error mentioning a certificate, often signed by unknown authority.

Why

Each PC checks that it is talking to your server, and not something pretending to be it. An enrolment code carries a fingerprint of the server's certificate for this. A PC connected by hand uses the file ca.pem instead. The error means what answered did not match: the server was reinstalled since the code was made, another device has the server's address, or a hand-copied ca.pem is the wrong one. Nothing was sent to whatever answered.

What to do

With an enrolment code: create a new code on the server (Settings → Licence and machines → Add a machine) and connect with that. If it still fails, another device on the network is using the server's address. Give the server a fixed address in your router.

Connected by hand:

  1. On the server, copy C:\ProgramData\BackupMate\Server\ca\ca.pem again (never ca.key, which sits beside it).
  2. Put it on the PC, for example at C:\ProgramData\BackupMate\ca.pem.
  3. Connect again, with that exact path in CA certificate file.

If the server was reinstalled, its certificate changed. Every PC must be connected again, with a new code.
